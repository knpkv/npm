# `@knpkv/herdr-connect`

Fleet agent directory and authenticated Herdr terminal control.

The directory combines the local inventory with peer `/v1/connect/agents/local` responses. Peer requests time out after 1.5 seconds and run with bounded concurrency. An offline, unavailable, timed-out, or malformed peer becomes a typed partial failure; healthy agents remain usable. The directory names each host that didn't answer, with its cause, above the list and in the Host filter, so missing agents are explained rather than silently absent.

The terminal connector resolves an opaque agent ID against the current local inventory, starts `herdr terminal session control`, streams Schema-decoded frames, and writes bounded input, resize, scroll, and release commands. Its session is scoped, so interruption releases or kills the child instead of leaving an attach process behind.

The connected terminal also exposes a touch-friendly key rail with fixed Escape, Tab, arrow, Ctrl, and Alt controls. Ctrl and Alt are one-shot modifiers: choose one, press a supported key or compatible terminal input, and the modifier clears after the typed `terminal.input` command is sent. Unsupported combinations are disabled or rejected; the rail never accepts arbitrary command text, and ordinary Ghostty input remains unchanged.

Copy is explicit: a mouse selection (drag, double-click a word, triple-click a whole line including the rows it wrapped onto) is copied with Cmd/Ctrl+C, which only sends ^C to the agent when nothing is selected. On touch, a long-press or the rail's Select key shows the screen as selectable text with Copy selection and Copy screen. Copied text has trailing spaces trimmed and wrapped rows joined; because herdr's screens carry no wrap marks, a row that fills the full width counts as wrapped. Cmd/Ctrl+click, or a tap on touch, opens http and https links in a new tab without an opener; other schemes are never opened.

herdr owns the scrollback and scrolls in whole lines, so touch scrolling draws the remainder on the client: the screen follows the finger 1:1, a flick carries on with iOS-style deceleration, and at most one scroll command is sent per frame. herdr keeps a pane's scroll position while output arrives and between viewers, so only the host knows where a pane really is. The connector reads it with `herdr pane get` and sends it as `terminal.scroll_state`, but only to a client that asked with `scrollState=1` on the session URL: an older client would close the terminal on a signal it cannot decode. The hub passes that opt-in on to the host that owns the pane, so a fleet can upgrade hosts and hub in any order. **A reading is used only when no scroll was in flight on either side when it was taken, so the offset already includes every scroll the client sent.** The connector reads only once no scroll was forwarded for 300 ms and herdr has drawn a frame since the last one (a scroll herdr never draws, clamped at an end, stops blocking after a second), and drops a reading if a scroll was forwarded while it ran. Each reading carries how many scrolls the session had forwarded, and the client uses it only if that equals the scrolls it actually wrote to its socket, so a reading that predates a scroll never lands however late it arrives, and the next quiet one does. herdr does not acknowledge scrolls, so this is how a reading is matched to them; the cost is that the count can trail active scrolling by about half a second. A known limit of that: a frame is taken as evidence that forwarded scrolls applied, and a scroll herdr draws no frame for counts as applied after a second, so a scroll herdr takes longer than that to apply, one overtaken by unrelated output, or several queued scrolls the first of which drew a frame, can be certified early; the next reading after it corrects the position. Closing that needs herdr to report the offset with its frames, an upstream ask. Reads happen when the session opens, after scrolling, as output arrives while the pane is scrolled back, and otherwise at most every two seconds while frames arrive, so a failed read or another viewer's scroll is picked up. They are coalesced and capped at two per second per session and ten per second across the host; a read past the host cap is not queued, but each session retries once when the host window frees, so the last read after scrolling still lands. A read that fails reports the position as unknown (`null`), never as the bottom, and is logged once per session; the client then keeps its own estimate, carried on from the last known position. While the pane is behind, the rail says how many lines with "Older output", and from there wheel, Page Down and touch scroll toward the newest output as far as the pane is back. Latest sends exactly that many lines, one command per frame and however deep the pane is, then waits up to five seconds for the next quiet reading — if none comes, the rail says "Position not confirmed" rather than implying the bottom: 0 ends it, anything else is output that arrived meanwhile, and a whole page follows (herdr clamps it at the bottom), so it lands there even while output keeps arriving. One known limit: Latest pressed before the first reading arrives (about half a second after opening) probes a page per frame, capped at 300 pages, so a pane more than 120,000 lines back needs a second press. The hub never drops a reading for good, locally or relayed from a remote host: under backpressure it holds the newest one until the socket drains. When the position is unknown, or the hub does not send it, the client falls back to its own estimate and Latest scrolls down a page per frame until the screen stops changing.

Browser consumers can import `@knpkv/herdr-connect/client` for the mounting entry, `@knpkv/herdr-connect/surface` for the embeddable state and view, and `@knpkv/herdr-connect/styles.css` for package-owned styles. Exact `host` plus stable `agent` query parameters select that room. The relationship store keys metadata by exact host and stable agent ID. Trusted live inventory may replace a stored parent only for the same host, stable agent ID, and pane with a strictly newer observation; durable, stale, equal, or pane-changing observations cannot reparent an agent. The view renders reported roots and parent relations; missing, cross-host, cyclic, or ambiguous ownership stays explicit and is never guessed.

Browser contracts are available through `@knpkv/herdr-connect/model`; browser subpaths do not pull SQLite or Node process code into the bundle. Its pure `agentStateBucket` helper shares the UI state classification with background consumers and returns `null` for unknown/new states.

The directory opens in Active. Its Archived link selects `?view=archived`, retained by refresh and Back/Forward. Archived reads one authenticated canonical-listener `/v1/connect/archive` page at a time, with up to 64 records. Show older appends the cursor's next page; failures retain loaded rows and expose Retry. Counts show a `+` while another page exists, and search covers loaded names, hosts, kinds and work only. Closures are keyed by host, stable agent ID and closure timestamp, so reopening a live ID does not merge its historical records.

An archived stage is read-only: first-seen and closure timestamps, state at close, kind, host, work, and optional full last words with their timestamp. Parent links require an already loaded active or archived record; unloaded parent IDs stay plain text. Agent-written words render as text. Archived stages do not expose pin, terminal or goal actions, or report a live stage for heartbeat handling.

`Creature.closed` defaults to false. For row, cast and stage presentations, it keeps the seeded outline with a neutral tint, shut lids and lowered brows, without a halo or motion while the prop is true. It is static with either reduced-motion preference and preserves the body's forced-colours outline. Clearing it resumes the current state's normal presentation.

`ConnectSurface.onStageChange` is an optional application callback receiving the open live stage's authenticated client-visible `{ host, id }`, or `null` on close and unmount. Reporting follows the stage identity, so replacing an inline callback does not close and reopen the reported stage. Reports use the latest committed callback. It observes live stages only; the application owns any reporting and persistence. The callback defaults to absent. The canonical hub uses it for invisible stage-viewing notification reporting.

`@knpkv/herdr-connect/usage` exports the existing `UsageSurface` and atoms, plus the stateless `UsageTab`, report loaders, selectors and view-state helpers for a host-owned page. `UsageTab` defaults to its Fleet presentation. Optional `presentation: { page: "limits" | "tokens", labelledBy }` omits its toolbar and h1; the owning page supplies the referenced h1, range control and conditional `AGENT_USAGE_PAGE` link using `onLoopback()`. Internal sections use h2 headings. Limits includes the current limit cards, tokens and limit history; Tokens includes its token chart and notes. The existing uncontrolled surface is unchanged. These reports carry only token and limit readings, with no cost, balance, booking, session, path or bot identity data.

## Agent voice

Agents can report a short status, progress update, skill feedback, note, or blocker through the canonical hub's authenticated `POST /v1/connect/posts`. Reports contain `agentId`, `kind`, `text`, `eventId`, and optional `goalStep`. The exported `connectPostTextLimit` sets status text to 240 characters and other kinds to 1024, measured with `string.length`. Posting schemas reject empty or whitespace-only text, preserving valid text unchanged, including URLs. Stored-report and last-words schemas still accept historical whitespace-only text. These are plain-text updates, never terminal transcripts or HTML. Consumers must render text as text.

The hub authenticates the calling Tailscale node, resolves its configured host, and accepts only a stable agent ID in that host's fresh, complete live inventory. Identity is host-bounded in v1: a process on the same host can claim a sibling agent's ID. The follow-up is a per-session token handed to each pane by Herdr and presented by the CLI. Other listeners reject voice requests.

`AgentPostStore` persists reports in owner-only SQLite beside the agent archive. Retries use the exact host, stable agent ID, and event ID; changed content with the same identity returns `Conflict`. Reports retain 90 days and at most 128 entries per host and agent. `GET /v1/connect/posts?host=HOST&agentId=AGENT` returns the newest 64, with `nextCursor.sequence` supplied as `cursor` for the next page. Reads require canonical listener authentication. `InvalidReport`, `UnboundAgent`, `Denied`, `Conflict`, and `Unavailable` name the report failures.

The newest retained report supplies the directory's optional `voice` text and timestamp. Confirmed closure snapshots those words as optional `lastWords` on the archive row. Existing archives migrate additively, and last words survive report eviction and reopening.
