`@knpkv/control-center` is a local, authenticated delivery application. It joins releases, work
items, pull requests, pipelines, runbooks, collaborators, evidence, and agent review without putting
provider credentials or server authority in browser code.

## Start here

Build and start the application:

```bash
pnpm --filter @knpkv/control-center build
pnpm --filter @knpkv/control-center start
```

Open `http://127.0.0.1:4173` and enter the single-use pairing code printed by the server. The first
paired person becomes the workspace owner. Durable data is written below `.control-center` unless
`CONTROL_CENTER_DATA_ROOT` selects another private application directory.

## Product model

Control Center stores traceability as a normalized delivery graph. Exact source revisions become
immutable entity projections. Directional relationships connect Jira work, pull requests, pipeline
executions, deployments, Confluence pages, and Clockify entries. Evidence has independent
verification, validity, and retention metadata, so expired evidence can stop proving readiness
without erasing its audit history.

The browser works with bounded, workspace-scoped projections:

- **Releases** keeps release identity, lifecycle, version, readiness, collaborators, source
  freshness, gaps, and related delivery work together.
- **Items** searches the authenticated workspace and opens canonical, URL-addressable entity pages
  and relationship evidence.
- **Services** discovers accounts and sites, configures followed resources, runs redacted connection
  tests, and exposes synchronization state.
- **Timeline** merges bounded governed-action, synchronization, relationship, and domain events with
  redacted export and owner-only inspection.
- **Active work** keeps durable PR-review jobs separate from the final human decision.
- **Relay** owns one browser-session thread per canonical release and always reloads the exact current
  release projection before a local agent turn.

## First-party providers

Provider descriptors negotiate each capability independently. The production catalog is
source-accurate at the current unstable schema snapshot:

| Provider     | Reads and synchronization                                           | Governed actions                                                                  |
| ------------ | ------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| CodeCommit   | Pull requests, immutable revisions, complete diff inventory/content | Request review, comment, request changes, approve, revoke approval; reconciled    |
| CodePipeline | Pipelines, executions, stages/actions, bounded logs/artifacts       | Start, stop, manual approval, and retry; reconciled                               |
| Jira         | Project issues, comments, changelog, people, bounded sync           | Revision-bound proposals only; provider execution and reconciliation are disabled |
| Confluence   | Space pages, lazy body reads, bounded metadata sync                 | Version-bound page publication and reconciliation                                 |
| Clockify     | Bounded time-entry reads and synchronization                        | Correct association and record Control Center-owned approval; reconciled          |

Every provider response is Schema-decoded before normalization. Browser configuration contains
secret references, never secret bytes. Safe reads can use the bounded retry policy; ambiguous writes
move to reconciliation and are not blindly replayed.

## Release-aware agents

Relay supports explicitly configured local Codex, Claude, and OpenAI-compatible providers. Release
chat is read-only and receives a bounded frozen release projection. Provider paths, credentials,
native session values, and raw failures remain server-only.

Immutable CodeCommit review is a separate opt-in worker. It clones the exact head into a private
workspace, strips remotes and credential helpers, verifies the object ID, and runs the selected model
inside `sbx`. Suggestions must anchor to the immutable diff and remain drafts until a human edits,
revalidates, and publishes them through the governed-action path.

## Presentation system

The browser application consumes `@knpkv/rly`. The [rly documentation](/rly/) covers package exports,
tokens, themes, and registry use. Its published [Storybook component catalog](/rly/catalog/) is the
visual source of truth for component states and accessibility examples.

The earlier CodeCommit-hosted Control Center prototype is retired from production routing. Approved
prototype files remain only as unreachable visual references. A build-graph boundary and ast-grep
rule reject static, computed, or glob imports from production code.

## Stability

The persistence schema is deliberately unstable. Fresh databases are created from one checked-in
snapshot, and existing databases and backups must match it exactly. There are no migrations in this
phase; recreate development data or restore a backup made for the same snapshot.
