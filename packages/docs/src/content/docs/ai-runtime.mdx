title: Agent Runtime
description: Build durable local-agent workers against one provider-neutral Effect protocol.

`@knpkv/ai-runtime` is the small interface between durable application workers and local AI providers. Codex, Claude, and test bridges can emit the same bounded event stream through this contract; the application remains responsible for authorization, durable jobs, leases, context snapshots, and reconnectable threads. Provider bridges land separately from this foundation package.

## Install

```bash
pnpm add @knpkv/ai-runtime effect
```

## Runtime boundary

An adapter implements one method:

```typescript
interface AgentAdapter {
  run(request: AgentRunRequest): Stream.Stream<AgentRuntimeEvent, AgentProviderError>
}
```

Provide it through `layerAgentRuntime(adapter)`, then consume `AgentRuntime` in an Effect worker. A successfully exhausted stream must finish with exactly one `completed` event; `AgentProviderError` is the alternative terminal for a failed run and must occur before completion. Output or failure after completion, duplicate completion, and successful exhaustion without completion fail with a typed `AgentRuntimeProtocolError`. Interrupting the consumer interrupts the adapter stream and is the shared cancellation mechanism. Adapters that acquire resources must return a properly scoped stream so interruption runs their provider finalizers.

## Durable continuation

`AgentRunRequest` captures the workspace, release, subject revision, provider, model, access level, and a context fingerprint. A resumed request contains only an opaque `AgentSessionRef` plus that fingerprint.

The reference is deliberately not provider-native session data. Keep the actual Codex or Claude continuation payload behind a server-only adapter store, and resume only when the stored fingerprint matches the new request exactly. Browser responses and ordinary thread events should never expose provider session state.

## Deterministic tests

Use `makeDeterministicAgent` to test worker claims, retries, restart recovery, and thread replay without launching a local CLI:

```typescript
const fake = makeDeterministicAgent({
  events: [
    { _tag: "started", providerRunRef: null, sessionRef: null },
    { _tag: "output", channel: "assistant", text: "No blocking findings." },
    { _tag: "completed", outcome: "success", sessionRef: null }
  ]
})

const program = Effect.gen(function* () {
  const runtime = yield* AgentRuntime
  return yield* runtime.run(request).pipe(Stream.runCollect)
}).pipe(Effect.provide(fake.layer))
```

`fake.requests` records the ordered requests so an acceptance test can prove that recovery preserved the intended release context and did not duplicate a claim.

## Structured tool execution

Use `runToolAgent` when a selected Effect AI model must explore through
application-owned typed tools and return a schema-validated result. The caller
supplies:

- Explicit instructions and JSON context.
- One `LanguageModel.Service`; the loop performs no provider fallback.
- An Effect AI `Toolkit.WithHandler`, which owns schema decoding and typed
  handler failures.
- A final output `Schema`.
- A visible wall-clock budget.
- An optional artifact sink for complete tool results larger than 64 KiB.

The returned stream is lazy and emits typed start, model-progress, tool,
usage, repair, output-validation, and terminal events. Consumer interruption
interrupts the active model call or tool handler. Budget expiration fails with
`ToolAgentTimeoutError`, while the default 64-step safety boundary emits a
`max-steps` terminal outcome.

This stateless interface has no approval-response exchange. A Toolkit with a
static or dynamic `needsApproval` policy fails configuration before the model
or a handler runs. Resolve approval in an outer workflow, or pass only tools
that are already authorized for the run.

The loop gives one malformed tool call or final JSON response exactly one
schema-guided repair turn. A second malformed response fails closed with
`ToolAgentInvalidResponseError`; missing values are never guessed or coerced.

Model-visible tool results are UTF-8 JSON bounded to 64 KiB. When a result is
larger, the caller's `ToolAgentArtifactSink` retains the complete JSON and the
model receives bounded head/tail excerpts, byte counts, and an opaque
`ToolAgentArtifactId`. Put caller-owned artifact paging and search tools in the
same Toolkit when the model needs the complete value.

Schema-valid `void` tool results are represented as JSON `null`. A tool call
marked as provider-executed keeps the provider's result in the next prompt and
does not invoke the corresponding local handler.

`makeToolAgentAdapter` projects these events into the existing
`AgentRuntime` stream. Validated final JSON is split across bounded assistant
output events instead of being aggregate-capped, preserving durable worker
integration without imposing a result or suggestion-count limit. Usage is
persisted only when both token totals are finite, non-negative safe integers;
unknown or partial totals are omitted rather than recorded as zero.
